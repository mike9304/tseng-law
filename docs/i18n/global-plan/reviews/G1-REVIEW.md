## (A) Verdict

**FAIL — 1 blocking, 7 fix, 9 note.**

The component itself is well built: SSR/hydration is safe, the portal escapes the
`.header-utility` stacking context correctly, the resolver reuse is genuine, and the
11-locale copy is good native-quality work with no compliance violations. It fails
on process, not craft: the header/drawer swap silently invalidated three existing
Playwright specs that guard the "every public page offers every language and no
option 404s" contract (WO-O22 A, G21), and nothing was added to replace that
coverage. On top of that, the mobile drawer path has two real defects that the
desktop-only browser QA could not have caught.

## (C) Checked and correct

- **SSR/hydration.** `usePathname() ?? \`/${locale}\`` (`:255`) is stable across server and client; `open` starts `false`, so the overlay renders on neither pass and there is no mismatch. `useId()` for `aria-labelledby` is SSR-safe. The `typeof document === 'undefined'` guard before `createPortal` (`:246-248`) is correct and keeps `GlobalLanguagePickerView` directly renderable under `renderToStaticMarkup`, which is what makes the unit tests possible. `useLayoutEffect` under SSR is an established pattern here (`Header.tsx`, `CinematicOpening.tsx`) and the build logs show no warning.
- **Portal vs. stacking context.** `.header-utility` is `z-index: 6` and therefore a stacking context (`globals.css:5497-5506`); portalling to `document.body` is the right fix and is why the full-screen overlay is not clipped by the utility bar. Above header (`6`), `header-main` (`5`) and the mega-menu.
- **Scroll-lock release on navigation.** `onClick={handleClose}` on each `<Link>` (`:206`) flips `open` before the route change, so the hook's cleanup restores `body.style.overflow`; unmount is covered by the same cleanup. No leak on the desktop path. (The mobile path is finding 2, a lost lock rather than a leaked one.)
- **Escape handling.** The `document`-level capture listener (`:142-149`) calls `preventDefault`/`stopPropagation` before the event can reach React's root listener, so the duplicate `onKeyDown` on the overlay fires at most once; `handleClose` is idempotent anyway. Working at 1440 per the new spec.
- **Focus trap and initial focus (desktop).** `usePublishedOverlayFocus` gives real Tab/Shift-Tab cycling over the close button plus 11 links, `focusin` recovery, and `initialFocusRef: closeButtonRef` as WO-G1 §3 required. Focus return to the trigger is asserted at 1440 in `global-language-picker.playwright.ts:61-68`.
- **Notice/href consistency — an improvement over the old switcher.** The picker derives both `notice` and `href` from the same `switchTarget` (`:187-200`). `LocaleFlagSwitcher` computed `isFallback` from `resolvePublicLanguageSwitchTarget` but the href from `localeFlagHref`, so it could show a fallback notice while linking somewhere else. That inconsistency is gone.
- **Column-slug context.** `usePublicColumnSlugs()` → `{ columnSlugsByLocale }` (`:83-85`) replicates `LocaleFlagSwitcher.tsx:121-124` exactly, including the `undefined`-when-absent behaviour that makes the resolver refuse to guess an article URL. Same-slug column links therefore still work from `/ja/columns/<slug>`.
- **Fallback notice coverage.** `fallbackLanguageNotice` reuses the vetted `unavailableLanguageNotice`, and `internationalInquiryCopy` has all 11 locales — no `undefined` deref for any current locale. The notice is surfaced three ways (visible `.notice`, `aria-label`, `title`).
- **`lang` attributes.** Every link carries `lang={publicLanguageHtmlLang(entry.locale)}` with `zh-Hant` correctly cased (`:202`), per WO-G1 §3.
- **Reduced motion.** `@media (prefers-reduced-motion: reduce)` disables both keyframes (`module.css:236-241`).
- **Touch targets.** Close button 44×44 (`module.css:97-99`), drawer trigger `min-height: 44px` (`:49-51`), and `.item` rows compute to ~63px from padding plus two text lines. The 390 spec asserts the close-button box.
- **Crawlability.** Removing 11 SSR `<a href>` language links from the header does *not* strip the site of crawlable per-page locale links: `Footer.tsx:258` still renders `LocaleFlagSwitcher`, whose `<details>` emits all 11 anchors in the server HTML regardless of open state. Given how load-bearing this repo treats inbound locale links (`public-route-policy.ts:33-37`, GSC 2026-09-02), worth stating explicitly — the footer is now the only SSR source, so it must not be swapped next.
- **H1 discipline (G1-R1 ①).** Dialog title is `h2`, region headings `h3`, no `h1` in the component; asserted both in unit (`:164-175`) and at 1440 in Playwright (`h1` count 1 before and after opening).
