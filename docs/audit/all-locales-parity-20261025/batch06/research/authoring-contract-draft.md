## 집필 입력과 서술

각 작가는 배정된 여섯 현재 정본을 메타데이터·본문·FAQ·출처까지 전문으로 읽는다. [six-source-facts.md](six-source-facts.md)는 놓치기 쉬운 조건을 찾는 표이며 정본을 대신하는 축약 원고가 아니다. [source-register.md](source-register.md)에서 공식자료의 실제 열람 범위도 확인한다. 새 언어의 최근 칼럼3편과 공통 문체 규칙, 프로젝트 문체 정본, COLUMN-VOICE-RULE.md, SENTENCE-VARIETY-RULE.md, LESSONS.md를 전문으로 읽고 적용한다. 이미 이 연속 작업에서 실제 읽은 규칙은 재독 횟수를 늘리기 위한 형식 작업을 하지 않는다. 접근하지 못한 파일은 읽었다고 기록하지 않는다.

목표 언어의 독자가 대만에서 겪을 계약·조사·분쟁을 자연스러운 문장으로 설명한다. 원문의 문장 순서·길이·접속어·소제목 틀을 복제할 필요는 없다. 법적 명제와 필요한 이유·증거·실무 설명은 완결되게 보존한다. 사실표에 추가 확인된 세부를 전부 넣거나, 정확한 정본 요약에 새 예외 목록을 덧붙일 의무는 없다. 범용 도입, 반복 훈계 제목, 추상적인 강조, 기계적인 목록, 번역투를 실제 문장 단위로 고친다.

독자 언어로 국적을 추정하지 않는다. 독일어·이탈리아어·힌디어·말레이어·러시아어라는 이유로 그 국가의 노동·소비자·부동산·중재·회사법을 추가하지 않는다. 아랍어는 여러 국가의 독자가 이해할 표준 문어를, 포르투갈어는 독자의 거주국을 단정하지 않는 자연스러운 표준 서술을 사용한다. 미국 공급자·투자자를 대상으로 한 ITA·USTR 자료의 원래 국가 맥락은 그대로 밝힌다. 그 혜택이나 자격을 대상 언어 국가에 치환하지 않는다.

## 출처·날짜·메타데이터

새 원고의 published·lastmod는2026-10-26이며 date_display는 해당 언어로 표시한다. 기존 정본의 원발행일을 소급 변경하는 작업은 아니다. audience는 실제 locale 하나를 쓰고, read_time·categories·title·seoTitle이 있다면 해당 언어의 자연스러운 용례와 실제 스키마를 따른다. summary와 FAQ는 본문보다 단정적이거나 넓어지지 않아야 한다. internal author는 legal-ai-assistant를 보존한다. 공개 저자명·검수자명을 임의로 추가하거나 인간·원어민·변호사의 검수 승인을 주장하지 않는다. 굵은 강조 및 strong/b 우회는 사용하지 않는다.

원문의 공식 URL과 출처 연결을 보존한다. 동일 기관의 대체 공식 경로를 실제 확인해 쓴 경우에는 저자 기록에 무엇이 같은 근거인지 설명한다. 링크 누락 검사를 통과하려고 출처를 삭제하거나 검사기를 느슨하게 하지 않는다. 관련 내부 칼럼 링크는 실제 목표 언어 경로가 있을 때만 그 경로로 옮긴다. 원문 경로를 유지할 필요가 있으면 그 링크의 언어를 오해하지 않도록 처리한다.

출처 확인일은 실제 행위를 반영한다. 이번26일에 현행법·정책을 다시 읽었지만919·920·915·916의 법원 접근은 실패하여25일의 실제 공식 회신을 재사용했다. 이 구별은 저자 기록에 남긴다. “26일에 판결문 전체를 새로 확인했다”는 표현은 사용하지 않는다. 공개 글에 도구 내부 과정을 장황하게 넣을 필요는 없으며, 판결 확정 여부처럼 독자의 판단에 필요한 한계는 분명하게 유지한다. 이 묶음만으로 USTR 협정 전체의26일 발효 상태를 단정하지 않는다.

표의 기존 이미지 경로를 사용하면서 실제 내용과 맞는 alt를 현지화하고, caption은 해당 언어로 “허구의 장면”이라는 뜻을 보존한다. 실제 당사자·사건 현장 사진으로 소개하지 않는다. 사무소의 공식 안내는 현재 확인한 상담 가능4언어 범위를 유지하며 새 칼럼 언어로 상담이 보장된다는 문장을 만들지 않는다. 사무소가 이 여섯 사건을 수행했다는 주장이나 타국 자격도 추가하지 않는다.

## 결과물과 확인 기록

작가는 여섯 원고와 자기 소유 저자 기록을 제출한다. 기록에는 정본 전체 SHA, 읽은 최근3편·규칙, 실제 수정한 문제 문장·이유·수정안·의미 보존, 최종 원고 SHA를 남긴다. 의미 확인에는 위 조건표와 실제 FAQ를 대조한 결과를 적고, 선택 문체 제안과 필수 사실 오류를 구분한다. 수정 전 오류나 검사 실패가 있었다면 이력을 보존한다.

공유 검사기는 실제 언어로 실행한다. 현재 공유49언어 설치에서 이 일곱 언어가 지원되므로 다른 언어로 우회할 이유가 없다. 실행 예시는 다음과 같다.

```sh
PATH=/Users/son7/.nvm/versions/node/v24.14.1/bin:$PATH PYTHONDONTWRITEBYTECODE=1 python3 /Users/son7/tseng-lanes-shared/variety/variety_metrics.py check <원고파일> --lang <실제-locale>
```

실제 exit와 FAIL/WARN·지표, 추출된 문장 경계, 규칙5절 자기 점검을 기록한다. 조문번호·판결번호·날짜·약어·아랍어 숫자 방향이 정상 문장을 잘못 자르지 않았는지 직접 읽는다. 구체적인 도구 결함은 담당자에게 재현을 전달하고 점수를 맞추기 위한 정상 조문 삭제·임계값 변경·의미 축소는 하지 않는다. 문체 검토는 `MONOTONY: 항목 — 문장 — 방향` 형식으로 남길 수 있다. 기계 PASS는 법률 의미나 인간 원어민 승인과 별개다.

마지막에 메타데이터·FAQ 수·링크·이미지·금액·기산·must/may·AND/OR와 원고 SHA를 확인한다. 정확한 최종본의 기록을 부모 에이전트에 전달하면 된다. 커밋·통합·공개 배포와 공개 화면 확인은 부모의 배정에 따르며, 연구 묶음이나 기계 검사만으로 이미 게시되었다고 보고하지 않는다.
