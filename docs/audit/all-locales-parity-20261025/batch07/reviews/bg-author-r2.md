# BG 독립검수 R1 반영 기록

2026-10-26. 부모가 승인한 M1·M2와 선택 O1만 적용했다. 기존 bg-author.md, bg-author-manifest.json, 초기 원고·도구 실패 기록, 독립검수 R1과 최초 입력 freeze는 보존했다. 이 기록은 저자의 수정 확인이며 독립 승인이나 공개 완료가 아니다.

## 실제 수정

정확한 전후 문자열과 위치, 백업·역복원 결과는 [bg-r2-edits.json](../checks/bg-r2-edits.json)에 있다. 여섯 치환 가운데 다섯 개는921, 한 개는916에 적용했다.

MONOTONY: 배치 도입 집중 —921 잔액 사실 문장 — 실제 환급 질문으로 바꿨다. MONOTONY:921 대비·별개 설명 반복 — 청구/인용, 해지/환급,7일/제18점, 보관/제공의 추상적 재설명 — 사건 결과와 실제 권리를 직접 썼다. 내용 있는 구별은 남겼으며 수동 검수에서 지적한 직접 대비 세 곳 외에 같은 틀의 재설명을 줄였다. 선택 O2 날짜 세 문장은 부모 결정대로 유지했다. 정상 `г.`를 제거하거나 공유 도구를 수정하지 않았다.

## 표적 검증

- 변경한916·921만 실제 공유 `--lang bg`로 검사했다. [실행 결과](../checks/bg-variety-r2-review.json)는 각각 exit0 / FAIL0, CV .484/.458, 분절42/40이다. 최초 래퍼가916의 OK 출력 뒤 기존 배열 키를 잘못 읽어 중단한 사실은 [별도 기록](../checks/bg-r2-wrapper-initial-error.json)에 남겼다. 실제 스키마를 읽은 뒤 두 변경본의 exit와 결과를 저장했다.
- [경계 차이](../checks/bg-boundary-delta-r2-review.json)의 여섯 변경 구간과 실제 주변 문단을 모두 읽었다.916은 한 완결문만 바뀌며42분절,921은 질문 전환·직접 진술·두 문장 통합·재설명 삭제로42→40이다. 날짜·조문·금액의 새 오분절은 발견하지 못했다. 나머지 네 편은 기존 SHA와 배열을 재사용한다.
- 두 현재 원고에 여섯 치환을 역순·정확한 위치로 역적용하여 R1 바이트와 SHA를 복원했다. frontmatter·FAQ·모든 링크 값과 순서는 불변이다. [916 diff](../checks/bg-r2-916.diff), [921 diff](../checks/bg-r2-921.diff)에 실제 변경만 있다.
- 실제 R 검사기로 두 변경본만 구조 검사한 [결과](../checks/bg-content-audit-r2.json)는 오류0, 의미검토 항목10이다. EN916/ZH921 정본 SHA가 동결값과 일치한다. 미변경 네 편의 기존 구조 결과를 지우거나 다시 돌리지 않았다.

5절 기준으로 금지된 가상 도입·꾸민 경험·굵은 강조를 추가하지 않았다. 짧은 문장·인용 없는 실무 문단·사건별 결말이 남아 있고, 법률 조건·기산·출처·허구 캡션의 삭제가 없다. 독립검수가 확인한 실제 최신 BG704–706의 전문 독해는 검수자의 기록으로 연결한다. 최초 저자가 직접 읽은885–887을 발행일 기준 최신3이라고 소급해 고쳐 적지 않았다.

915의 기존 `г.` 뒤 대문자 주어를 둘로 자르는 공유 추출 한계는 그대로다. 그 원고와 수동 민감도 기록을 변경하지 않았으며 이번 두 파일 PASS를 그 경계의 해결로 확대하지 않는다. 인간 원어민·법률 감수, 실제 표시·공개 배포 승인을 주장하지 않는다.
