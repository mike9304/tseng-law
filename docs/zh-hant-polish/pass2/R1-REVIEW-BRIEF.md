## 첨부 2: docs/columns/EDITORIAL-VOICE.md
# 공개 글과 사이트 문구의 문체 규칙

2026-09-30 사용자 요청으로 작성. 칼럼·제목·요약·메타 설명·버튼·캡션·번역·문체 검수에 적용한다. 특정 모델의 취향이 아니라 이 작업공간의 공통 편집 기준이다. 사용자가 별도 문체를 지정하면 그 요청을 따른다.

## 쓰는 기준

- 독자가 궁금해하는 사실이나 질문부터 쓴다. 글을 어떻게 전개할지 예고하는 문장은 생략한다.
- 첫 문장을 지워 보고 사실·조건·맥락이 줄지 않으면 지운다. 제목을 되풀이하거나 독자의 고민을 대신 말하는 문장, 길게 꾸민 상황 도입으로 시작하지 않는다. 필요한 전제·안전 안내·법적 의무는 보존한다.
- 주체와 행동을 드러낸다. “검토가 이루어집니다”보다 누가 무엇을 검토하는지 쓴다. 주체를 모르면 만들어 채우지 않는다.
- “도움이 됩니다”, “중요합니다”로 끝내지 말고 무엇에 도움이 되는지, 왜 필요한지 근거가 있는 범위에서 설명한다. 설명할 내용이 없으면 문장을 뺀다.
- 제목에는 그 글만의 대상과 쟁점을 담는다. 모든 제목을 질문형·명령형·“A부터 B까지”로 맞추지 않는다. 검색어를 억지로 반복하지 않는다.
- 한국어 법률 칼럼 본문은 차분한 합니다체를 기본으로 한다. 제목은 명사구나 자연스러운 질문도 쓴다. 친근함을 위해 반말·과장·느낌표를 덧붙이지 않는다.
- 한 문장에 쟁점을 몰아넣지 않는다. 다만 모든 문장을 짧게 끊거나 문단 길이를 똑같이 맞추지도 않는다. 연결된 생각은 문장과 문단으로 이어 쓴다.
- 목록은 실제 순서·준비물·비교 항목이 있을 때 쓴다. 단락마다 세 항목, 같은 길이, 같은 어미로 맞추는 구성은 피한다. 표는 비교할 기준이 있을 때 쓴다.
- 도입→세 가지 핵심→체크리스트→상담 권유 같은 틀을 모든 글에 반복하지 않는다. 필요한 정보가 끝나면 끝낸다. 결론에서 본문을 다시 요약할 필요는 없다.
- 상담 안내는 필요할 때 짧게 한 번 쓴다. 불안감을 키우거나 결과를 보장하지 않는다. 버튼은 “상담 문의”, “자료 신청”처럼 실제 행동을 짧게 표시한다.

## 먼저 의심할 표현

다음은 문맥을 살펴 고칠 신호다. 단어 목록을 기계적으로 지우는 규칙이 아니다.

| 습관 | 수정 기준 |
|---|---|
| “이 글에서는 … 알아보겠습니다”, “지금부터 살펴보겠습니다” | 예고를 빼고 내용으로 시작한다. |
| “핵심은”, “중요한 것은”, “꼭 기억하세요”, “반드시 확인하세요”의 반복 | 강조 대신 실제 차이·조건·이유를 쓴다. |
| “단순한 A가 아니라 B”, “A를 넘어 B”, “새로운 패러다임” | 논점에 필요한 대비인지 확인한다. 의미 없는 수사라면 지운다. |
| “급변하는 시대”, “복잡한 현대사회”, “다양한 니즈”, “최적의 솔루션” | 해당 글의 구체적인 대상·상황으로 바꾼다. 근거 없는 최상급은 쓰지 않는다. |
| “~에 있어서”, “~을 통한 ~의 실현”, “~라고 할 수 있습니다”의 연속 | 주체와 동사로 풀어 쓴다. 실제 가능성·불확실성은 남긴다. |
| “먼저 / 다음으로 / 마지막으로”, 굵은 소제목과 요약의 반복 | 실제 순서일 때만 연결어를 남긴다. 읽히는 문단이면 충분하다. |
| “이해하셨나요?”, “여러분의 소중한 권리”, “지금 바로 전문가와…” | 훈계·감정 유도·습관적인 홍보 문장을 뺀다. 필요한 안내만 남긴다. |

## 문체를 고쳐도 보존할 내용

- 법적 의무·금지·허용·권고를 구별한다. 실제 의무인 “해야 합니다 / 應·須 / must / ～しなければならない”를 권고로 약화하지 않는다. 안전 안내·실제 절차의 명령형도 필요한 경우 그대로 쓴다.
- 관할, 당사자, 신청 자격, 조건의 AND/OR, 예외, 기산점, 기간·금액·단위, 신청 가능일과 발급일의 차이를 보존한다. 제목과 요약에서도 본문보다 넓게 단정하지 않는다.
- 반복되는 포괄 면책 문구는 줄일 수 있다. 적용 범위와 불확실성에 필요한 단서는 남긴다. 확인하지 못한 사실은 자신 있는 문장으로 덮지 않는다.
- 인용문은 원문 그대로 둔다. 출처 링크와 인용이 뒷받침하는 주장의 관계를 유지한다. 문체 수정 중 사실을 바꾸면 별도의 사실 검증을 거친다.
- 사건, 통계, 상담 경험, 고객 반응을 만들어 문장을 생생하게 하지 않는다. “변호사로서”, “우리가 맡은 사건”, “대만에서 10년 살아보니” 같은 신분·경험을 꾸미지 않는다.
- tseng-law의 `author: legal-ai-assistant` 및 AI 작성자 표기를 유지한다. AI의 문체 검수를 “원어민 검수 완료”나 “변호사 검토 완료”로 표시하지 않는다. 자연스러운 문장이 목적이며 작성 주체를 숨기는 작업이 아니다.
- 연락처·작성자·출처·게시 승인에 관한 프로젝트 규칙을 유지한다. 이 문체 규칙은 게시 허가나 법률 검증을 대신하지 않는다.

## 번역도 다시 쓴다

- 한국어의 문장 순서·소제목·문장 수를 그대로 복제하지 않는다. 해당 언어에서 자연스러운 순서로 쓰되 주장과 근거를 보존한다.
- 한국어: 명사와 “~의”를 길게 잇지 않는다. 불필요한 피동과 “~라고 할 수 있습니다”를 줄인다. 법률 용어는 필요한 곳에서 설명한다.
- 대만 번체: 대만에서 쓰는 어휘와 공식 기관·법령 명칭을 사용한다. “本文將帶您了解”, “值得注意的是”를 반복하지 않는다. 應·得·須의 의미 차이를 유지한다.
- 영어: 주체와 동사를 앞에 놓는다. “delve into”, “navigate the complexities”, “it is important to note”, “comprehensive guide”를 관성적으로 붙이지 않는다. must / may / should를 구별한다.
- 일본어: 본문은 자연스러운 です・ます체를 기본으로 한다. “〜について解説します”, “重要なポイントです”를 반복하지 않는다. 제목까지 억지로 ます체로 맞추지 않는다. 義務·可能·推奨을 구별한다.
- 다른 언어에도 같은 기준을 적용한다. 해당 언어의 자연스러움을 판단하기 어렵다면 검수 한계로 남긴다. 모델이 검토했다는 사실을 현지인의 검토로 바꾸지 않는다.

## 작성·검수 절차

1. 작성자·번역자·검수자는 시작 전에 이 파일 전문을 읽는다. 외부 API나 파일 접근이 없는 모델에는 경로만 보내지 말고 전문을 프롬프트에 넣는다. 원문·출처·작업 지시와 구분해 전달한다.
2. 초안 뒤에 제목·소제목·첫 문단·마지막 문단·버튼·요약을 별도로 읽는다. 범용 도입, 지시형 제목의 반복, 추상적인 설명, 번역투가 있으면 실제 문장으로 고친다.
   - 첫 두 문단은 한 문장씩 삭제해 보고 정보 손실 여부를 검수 기록에 남긴다. 삭제해도 내용이 같으면 본문에서 뺀다.
   - 직전에 게시한 같은 언어의 글 3편과 도입·소제목·끝맺음을 비교한다. 같은 틀을 반복했으면 해당 글의 쟁점에 맞춰 고친다.
3. 문체 검수자는 `원문 → 문제와 이유 → 수정안 → 보존한 사실·조건`을 기록한다. “AI스럽다”, “더 자연스럽게”, “AI 티 없음”만으로 판정하지 않는다. 관련 없는 기술 작업에는 이 절차를 추가하지 않는다.
4. 수정 전후의 인용·숫자·조건·부정·법적 강도를 대조한다. 번역은 원문과 함께 확인한다. 기존 사실 검증과 프로젝트의 최종 승인 절차를 유지한다.
5. 남은 중대한 지적과 검수 범위를 명시한다. 임의 점수·AI 탐지기·금칙어 검색만으로 통과시키지 않는다. 통과한 글을 끝없이 다시 고치지 않는다.

통과 기준: 제목이 실제 내용을 말하는가, 첫 문단이 바로 정보를 주는가, 문장마다 새 내용이 있는가, 구성·어미가 기계적으로 반복되지 않는가, 각 언어에서 자연스러운가, 의미·출처·작성자 표기가 유지되는가. 검수 기록은 내부 산출물로 두고 독자용 본문에 넣지 않는다.

## 작업 답변과 화면 구성

- 사용자에게 답할 때도 결과나 필요한 행동부터 말한다. 동의·칭찬·질문 재진술·답변 예고를 관성적으로 앞에 붙이지 않는다. 판단 근거와 남은 제한은 필요한 만큼 설명한다.
- 칼럼 화면은 글의 구분과 탐색에 필요한 요소부터 배치한다. 같은 정보를 제목·소개·번호 카드·요약으로 반복하지 않는다. 장식용 카드·배지·도해를 추가하기 전에 독자가 무엇을 더 이해하는지 확인한다.
- 문체 규칙을 전달했다는 사실만으로 좋은 문장이 보장되지는 않는다. 자동 검사는 규칙 전달 누락을 잡고, 최종 검수자는 실제 문장과 화면을 읽는다.
