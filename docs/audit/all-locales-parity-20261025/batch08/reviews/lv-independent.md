그 과정에서 도구 동등성 guard가 실제 한 번 중단됐다. 이전 expansion SHA `c8f5368fa0d8747e96ac9483c37227155083cb10a3e687fca2b10bca7add82bc`와 현재 `ea03abaa59249d7d914e1c98a5231a5c1636528dd1ecda326b0d4638edf17975`의 차이를 감지한 것이다. [실패와 이전 스크립트](../checks/lv-independent-tool-change.json)를 보존하고 root의 설치 receipt를 읽었다. metrics `5abf02…`, multilingual `4af341…`, LV profile `09dc74…`는 그대로다. 새 설치에서의 직접 추출이 같은 결과였다는 증거를 추가했으며 과거 CLI를 새 도구 실행으로 바꾸지 않았다.

249개 실제 배열에서 연도·날짜(`2017. gada 12. jūlijā`, `2026. gada 17. septembrī`), 조문(`85-1. pantu`, `40. panta pirmās daļas 2. punktā`, `154. pants`), 페이지 범위(`173.–187.`), 공백으로 묶은 두 금액을 직접 확인했다. 정상 서수점 때문에 분절된 조문이나 날짜 조각은 발견하지 못했다. 표 앞 설명은 문장 통계에 포함되고 표 자체는 제외되는 범위도 확인했다.

1. 여섯 현재 SHA의 실제 CLI는 FAIL0이고, 현 도구 직접 추출도 같은 배열·지표다. 최초 919/920 CV 실패와 저자 교정 기록은 그대로다.
