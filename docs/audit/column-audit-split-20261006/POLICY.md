# 분할·축약 정책 v1 (2026-10-06, 리드 Opus × Fable 5.1 토론 합의)

## 판정
- 후보 선별: 측정 길이(inventory.tsv, 출처 제외)가 언어 중앙값의 1.8× 이상. **선별용일 뿐 판정 기준 아님.** read_time 값은 수기라 쓰지 않는다.
- KEEP: 길어도 독자 질문 하나에 집중(판례 해설·단일 절차 등). 군더더기만 있으면 TRIM.
- TRIM: 중복(FAQ↔본문, 같은 내용 재요약, 1문단 스텁 문항이 앞 문항 재요약), 전개 예고, 반복 유보문을 뺀다.
- HUB-TRIM: 덩어리 주제를 **같은 언어의 기존 전용 칼럼이 같은 깊이로** 다루면(절 단위 커버리지 표로 확인) 그 절은 기존 리드 문단 1개 + 링크로 줄인다.
- SPLIT: 독자 질문·검색 의도가 다른 덩어리 2개 이상, 전용 칼럼이 없고, **분할 후 각 편이 그 언어 중앙값의 0.6× 이상**일 때만. 각 편 독립적으로 읽혀야 한다.

## 언어
- 같은 slug 4개 언어판을 같은 모양으로 맞추지 않는다. 평행 유지는 제목/H1과 핵심 절차 코어만. 나머지 절은 언어별 전용 칼럼 보유에 따라 판정.
- 새 편을 여러 언어로 같은 slug로 만들면 hreflang 자동 클러스터, 한 언어만이면 self-canonical — 둘 다 허용.

## URL·번호·프런트매터
- 기존 slug = 1편(허브)으로 유지, 리다이렉트 없음. 새 편은 새 번호·새 slug. 번호는 ship 직전 origin/main에서 `src/content/columns*/NNN-*` 부재 확인 후 Studio `register.py` 규약으로 등록(배치 단위로 묶음).
- 시리즈 링크는 본문 마크다운으로(관련/시리즈 프런트매터 없음).
- FAQ: 허브에서 요약+링크로 바뀐 절의 FAQ 항목은 허브에서 제거하고 새 편(있으면)으로 옮긴다. FAQ 답은 그 편 본문과 일치해야 한다. FAQ 답을 본문 문단에 통째로 복사하지 않는다.
- lastmod 오늘, read_time 재계산(ko·zh 약 500자/분, ja 약 600字/분, en 약 230 words/min).

## 변호사 명의(author 필드 없음, 001–018)
- 공개 표기는 "이 글 검토 변호사". 요약을 새로 쓰지 않는다 — 기존 문장을 고르고 옮긴다. 연결문은 최소, docs/audit에 문장 단위로 기록.
- 변호사 명의 문장을 legal-ai-assistant 칼럼으로 옮기거나 그 반대로 섞지 않는다(링크만).
- 새 편이 변호사 명의 글에서 옮긴 것이면 author 비움(변호사 byline 유지). 최종 보고에 "변호사 직접 검토 미경유" 명시.
- 허브가 링크하는 legal-ai-assistant 칼럼은 사실점검(B) 대상에 편입.

## Studio 레인과의 조정
- slug 단위로 Studio 4개 언어 항목이 모두 shipped이거나 미착수일 때만 착수. 미착수면 4개 언어 `.parked`(형식 `YYYY-MM-DD HH:MM:SS 사유`) 후 착수, 우리 배포 후 삭제.
- factfix jobs(`~/tseng-rewrite-1006/factfix/jobs/<slug>-*`)에 같은 slug가 있으면 착수하지 않는다.
- push 전 Studio `/tmp/gap1006-ship-lock`·`/tmp/cols1006-ship-lock` 부재 확인. 레지스트리를 바꾸는 배포 후 Studio에 영향(tests.patch) 기록.
