# BG 915·916·918–921 저자 기록

상태: 집필·자체 의미/문체 확인 완료, 원고 동결. 실제 공유 CLI 6편 exit 0 / FAIL 0, 구조 오류 0. BG915의 날짜 약어 뒤 한 문장은 도구가 두 조각으로 나누는 한계가 있어 수동 완결문 확인을 따로 기록했다. 이 제출은 독립 의미 검수, 인간 원어민 승인, 인간 법률 감수 또는 배포 완료를 뜻하지 않는다.

## 입력과 소유 범위

- B7 BRIEF 전문을 읽었다. SHA `8103ae1441fe0abbdb76362d6086a267014664f31997f5676b37c6962cfcd306`.
- B6의 현재 정본 여섯 전문, 사실표, source-register, source-freeze, authoring-contract를 직전 연속 작업에서 읽었으며 같은 SHA를 재사용했다. B6 다른 언어 초안을 번역 원문으로 사용하지 않았다. 승인본과 ZH918/920/921의 metadata-only 정규화 사슬을 구별한다.
- R의 문체 정본, COLUMN-VOICE-RULE, SENTENCE-VARIETY-RULE, LESSONS 전문을 읽은 동일 SHA에서 계속 작업했다. 홈 `agent-library/knowledge/editorial-voice.md`는 없으므로 읽었다고 기재하지 않는다.
- 실제 최근 BG885·886·887 전문을 각각 읽었다. 언어가 독자의 국적이라는 전제를 이 새 여섯 편에 옮기지 않았다. 문의 언어에 불가리아어를 추가로 약속하지 않았다.
- [입력 동결](../checks/bg-input-freeze.json)과 [종료 무결성](../checks/bg-input-integrity.json): 기록한 24개 입력 SHA 모두 동일. 정본별 R 파일은 구조 검사 시 동결 snapshot SHA와 다시 대조했다.
- 수정 범위는 B7 BG6, 이 저자 기록, `checks/bg-*` 및 부모가 추가 허용한 `tooling/bg-date-boundary/` 진단뿐이다. R·공유 도구·타 언어·타 검수 기록은 수정하지 않았다. 커밋·빌드·배포하지 않았다.

## 실제 경계와 5절 점검

[최종 추출 배열](../checks/bg-boundaries-final.json)의 기계 분절은 합계 251개다. 초기 배열을 전부 읽고 [실제 변경 배열](../checks/bg-boundary-delta.json)의 모든 바뀐 부분을 다시 읽었다. 마지막 출처 점 정리 전후 측정 문단과 배열은 완전히 동일했다. 법원 사건번호, 85-1·22-2, 6(1)(4), 금액의 공백, 날짜와 약어를 확인했다.

915의 `В решение ... от 12 юли 2017 г. Върховният съд...`는 완결문 하나인데 CLI가 두 조각으로 나눈다. 직접 읽은 본문 완결문은 42개이며 이 문장의 정상 표기는 유지했다. [수동 민감도 기록](../checks/bg-915-manual-boundary-impact.json)의 같은 단어 단위 CV 약 .541, 짧은 문장 비율 .333은 참고 산술이지 공유 결과를 대체한 합격 판정이 아니다.

[날짜 진단](../tooling/bg-date-boundary/README.md)에는 중립 14예문 중 실제 기대 일치 9/14, 제목 처리와 반례가 있다. 연도 뒤 대문자를 전부 병합하면 진짜 두 문장을 망가뜨리므로 자동수정 후보는 제출하지 않았다. 다른 48언어, BG 임계값·단위 및 공용 코드 모두 무수정이다.

5절 자체 확인: 가상의 일반 도입 대신 각 사건의 사실이나 구체적 쟁점으로 시작한다. 짧은 문장이 각 편 두 개 이상 있고 긴 법적 조건문과 섞인다. 동일 문단 시작·연속 동일 시작·길이 평탄화의 실제 FAIL을 남긴 뒤 수정했다. 조문만 세 문단 연속 같은 틀로 끝내지 않으며, 반대 문형은 법적 구별이 필요한 곳에 둔다. 사건별 말미는 제출기록, 보고서/자금흐름, 사용허가/통지, 청문기록, 배선경로, 결제/잔액으로 달리 끝난다. 같은 문의·출처 기능을 두었다고 서로 다른 사건의 요건을 같은 틀로 치환하지 않았다. 질문을 점수 때문에 새로 끼워 넣지 않았다.
