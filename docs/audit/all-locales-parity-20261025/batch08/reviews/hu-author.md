별도로 연도로 시작하는 5파일의 6문단에서 `2018.` 등의 점을 `2018\.`로 escape했다. 실제 R의 ReactMarkdown/remark-gfm에서 원형은 `<ol start="2018">`로, escape형은 날짜가 그대로 보이는 `<p>`로 렌더됨을 중립 예문으로 재현했다. 문장·숫자·법률 뜻을 점수에 맞춰 바꾼 작업이 아니다. `checks/hu-date-markdown-edits.json`에 정확한 여섯 변경과 역복원, `hu-date-render-neutral.json`에 실제 HTML이 있다.

## 문체 5절과 최근 글 비교

첫 두 문단을 문장별로 확인했다. 915는 권고 대상인 공기·금전의 질문과 판정액·최종 취소, 916은 실제 보고서·지배·자산 이동 및 근로자 노출 사건의 날짜, 918은 편지 내용·주택 상태·인도 미인정과 판결 결과, 919는 취소 사유·공무원 범위·상소 가능, 920은 배선 범위·재판 결과, 921은 청구액·미사용 점수 부존재·칩의 한정된 판단이다. 일반 인사나 글 예고를 넣지 않았다.

도입은 질문형 915/920, 문서·구체 사실형 916/918, 결과형 919, 숫자형 921이다. 한 유형이 절반을 넘지 않고 장면형은 없다. 최근 ARC704의 입국 기산, 705의 자격 비교, 706의 체류 근거 소멸 질문을 복제하지 않았다. 본문 독자 질문은 2/2/1/1/1/1개이며 소제목·FAQ와 분리했다.

실제 소스 문단의 시작을 세로로 읽고, 동일 단어로 시작하는 문단이 세 개 쌓이지 않는지 확인했다. 본문 긴 조건문은 같은 문단에 둘을 넣지 않았다. HU06·HU07에서는 연결된 조건·시간 관계를 다시 썼으며 마침표만 제거하지 않았다. 짧은 문장은 판정 불유지, 조정 권고, 기한 도과, 상소 가능성, 법정 최소 기간 등 구체 사실에 쓰였다.

인용을 주어·중간·끝에 분산했고 출처 없는 실무·문서 문단도 있다. 세 문단 연속 주장→괄호 조문→예외 틀은 없다. 기계 대비어 탐지 0은 모든 부정문이 없다는 뜻이 아니다. 단순 소유만으로 책임 없음, 현행법의 비소급, 모두 무효·모두 무권리로 확대할 수 없음 등은 원문의 법적 한정으로 남겼다.

실질 결말은 공통 고지 직전에서 각각 신청서·변경·회신의 시간순서, 조사 발견과 후속 자산 이동 결정, 대출·검사·인도 통지의 구분, 통지·진술·채택 사유, 승인 전 착공과 거절 시 비용, 입금부터 사용까지의 기록으로 끝난다. 판촉·결과 보장이나 정형 요약 결말이 아니다. 일반 정보 고지는 별도 꼬리다.

굵은 강조·HTML 우회·꾸민 1인칭·국적 단정·헝가리어 상담 보장은 없다. 제목·요약·태그·FAQ·alt는 헝가리어이며 caption은 정확히 `Kitalált jelenet`이다. 공개 작성자·검수자 이름은 추가하지 않았다.

초기 실제 shared CLI는 Node24를 PATH 앞에 두고 `--lang hu`로 여섯 파일을 실행했다. 결과는 다음과 같으며 실패를 삭제하지 않았다.

최초 수집 스크립트는 모든 CLI 실행 뒤 잘못 입력한 `multilingual.py` 경로의 해시를 읽다 JSON 저장에 실패했다. 동일 원고를 다시 CLI 실행하지 않고 실제 도구 출력의 exit/stdout을 `hu-variety-initial.json`에 복원했다. stderr는 소실 사실을 기록했다. 문장·지표 배열은 변경 없는 최초 SHA에서 재추출했으며 새 CLI인 것처럼 기록하지 않았다.

첫 진단에서 날짜 문단 누락을 도구 오류 후보로 알렸으나, 실제 Markdown 렌더러도 번호 목록으로 읽는 것을 확인하고 정정했다. 목록 정규식을 완화하지 않았다. 화면용 escape 적용 후 현행 문장 분리기가 `2018\.`를 독립 문장으로 자르는 별도 문제는 `hu-date-escape-neutral-checker.json`에 중립 재현으로 남겼다. root가 별도 담당자에게 후보를 배정했고, 저자는 공유 도구를 수정하지 않았다.

현재 ReactMarkdown의 실제 표시 문단에서 223문장을 추출해 전체 산문·초기 배열·새로 들어온 날짜 문장과 변경 문장을 대조했다. 이는 `hu-rendered-boundaries-review.json`의 수동 경계 검수이며 소스 파일을 대상으로 한 공유 CLI PASS를 대신하지 않는다. 5파일 6연도점은 이제 본문 문단으로 표시되고 의도하지 않은 ordered list는 0이다. 전체 페이지·모바일·브라우저 검증을 했다는 뜻은 아니다.

초기 구조검사는 수정하지 않은 R content-audit로 EN2/ZH4 정본 매핑을 지정해 errors 0이었다. 현재본은 FAQ17, 원문 공식 URL 23개 전부 포함, 본문·말미 출처 유지, 표 2개, 날짜·내부 author·locale·이미지·caption 일치를 확인했다. 공식 URL은 4/3/4/4/4/4개다. 916 내부 링크는 실제 R의 헝가리어 회사 설립 글이며 `/en/contact`는 영어 페이지임을 문구에 밝혔다. 외부 연락처는 기존 허용 이메일만 사용했다.

`hu-precheck-integrity.json`에서 실제 변경을 역순으로 되돌리면 여섯 원고 모두 최초 SHA와 일치한다. Frontmatter/FAQ, 모든 링크 값과 순서, 숫자 토큰은 불변이다. 마지막 공유 검사와 변경 후 구조검사를 이어 기록할 예정이다. 이 상태는 출판 준비 완료가 아니다.
