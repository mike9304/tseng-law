보존 판결 L44의 제6조 제1항 제4관 법률상 분류는 관리위원회인 피상소인의 진술이다. 수정문은 이를 주민에게 귀속하던 사실 오류를 제거하고 법원이 본건을 해당 조항의 상황으로 보지 않았다는 판단을 보존한다. 법 제11조·규약 제15조, 제6조 제1항 제5관·제3항, 실제 공용부분 위치와 개별 규약이라는 한계는 그대로다. 오류 자체를 보존해야 할 의미라고 취급하지 않았다.

FAQ1의 `未接受仅属专用部分增设管线的抗辩`는 별개로 L43 주민인 상소인의 전용부분 주장에 근거한다. 따라서 해당 FAQ를 유지하면서 본문의 제6조 제1항 제4관 귀속만 중립화하는 것은 모순되지 않는다. FAQ2의 정지·잠금·열쇠 제공은 가정적 판단이고, FAQ3의 보조금 범위와 종료 기한도 바뀌지 않았다.

## 독립 바이트·실행 확인

[독립 감사 스크립트](../checks/zh-hans-independent-r2-audit.py)를 직접 실행해 terminal exit 0을 확인했다. 작성자 체크리스트만 신뢰하지 않고 수정 전 바이트, 현재 파일 및 원래 독립 r1을 다시 대조했다.

- 원본에서 요청한 문장이 정확히 한 번 존재하고, 그 한 문장 치환 결과가 현재 파일 전체 바이트와 같다. 새 문장을 원래 문장으로 역치환하면 원본 전체 바이트와 정확히 일치한다. [독립 diff](../checks/zh-hans-independent-r2-exact.diff)도 한 문장 교체만 나타낸다.
- 메타데이터 원문과 파싱값, 제목·요약·FAQ3, 숫자 순서, URL 순서는 변경 전후 동일하다. 다른 5편은 각각 r1 SHA와 같고 묶음 FAQ17도 유지된다.
- 작성자 r6 manifest SHA는 `51c1839f4c8280c0a674299c5cc9f80b72fba492873fb078394e858848df6c78`, 보고서 SHA는 `2c9cf5cf368a2e7ff64ae623045509ba62a14860d9a68f64081bd1786bdfe41c`로 인계값과 같다.
- 수정된 920에 대한 작성자 실제 공유 CLI command는 올바른 현재 경로 및 `--lang zh-hans`이고 exit 0, stdout `OK — no variety limit violated`, stderr 없음이다. CLI가 실행된 SHA와 현재 SHA 및 공유 도구 SHA가 일치한다. 이 실제 실행 영수증을 재사용했으며 독립 검수자가 CLI를 새로 실행했다고 주장하지 않는다.
- 공유 함수로 실제 배열을 다시 산출해 P7 S1만 위 새 문장으로 바뀌었고, 나머지 모든 문장과 문단 경계가 같음을 확인했다. 36문장/13문단, CV .471, 짧은 문장 11.1%, 같은 길이 3연속 .059, 문단 시작 반복0, 대비0, 질문2다. 마지막 확인일과 사건 범위 두 문장은 계속 본문 배열에 포함된다. 출처 목록은 `## 官方资料`에서 제외된다.
- §5의 시작·종결·짧은 문장·긴 문장 연속·인용·반복은 변하지 않았다. 새 문장의 길이도47로 원문과 같으며 기존 길이를 맞추기 위한 다른 문장 편집은 없다. 법적 의미와 주장 주체 오류를 바로잡은 교정이다.
