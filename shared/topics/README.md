## 이번 라운드의 공통 범위

본문과 첫 댓글은 각각 500 코드포인트 이하로 작성한다. `body.md`에는 공개 본문만, 검수용 주석·출처 설명·버전 안내는 NOTES에 둔다. 첫 댓글은 답할 범위가 분명한 질문 하나와 판결 원문 링크를 담을 수 있다. 법률 결과를 독자 투표에 맡기거나 상담을 유도하지 않는다.

본문만 읽어도 사건·결론·그 결론에 이른 이유가 이어져야 한다. 모든 부수 항목을 억지로 넣는 대신, 해당 편이 다루는 쟁점을 끝까지 설명한다. 필요한 조건을 글자 수 때문에 없애면 반려한다. 장문 첨부가 필요하면 별도 파일로 제안하되 본문 이유 설명을 대신하지 않는다.

카드는 기존 5~6장을 출발점으로 삼을 수 있다. 첫 카드에 무슨 사건인지와 결론을 보이고, 마지막 카드는 그 사건에서 얻을 구체적인 정보로 끝낸다. 구 브리프의 ‘판결은 4~5장까지 숨기기’, ‘변호사 한마디’는 현행 기준이 아니다. 1080×1350, 가상 장면과 실제 증거 인용을 구별하고 인물 실명·회사명·주소·차량번호는 옮기지 않는다. 카드의 재구성 고지는 공개 표기 금지 항목과 별개다.

첫 두 줄은 사건과 결과를 일상어로 설명하는지 실제로 읽어 판정한다. 파일에 긴 문단 두 개를 넣고 ‘두 줄 통과’라고 세지 않는다. 코드포인트 검사는 길이 확인일 뿐, 휴대전화 피드의 실제 줄바꿈·사람 독해 시험을 대신하지 않는다.

## 채점과 인계

Astra는 첫 두 줄, 사실·판결 이유, 화자, 문체, 독자에게 읽을 이유, 참여 위치, 마지막 정보, 표기·길이의 8개 항목을 각각 PASS/FAIL/HOLD로 판정한다. 문제 문장·이유·수정 방향·의미 보존을 남긴다. 사실 오류를 다른 항목의 점수로 상쇄하지 않는다. 모두 통과한 초안끼리는 이야기 흐름과 구체성을 비교해 승자를 고른다. 승자 지정은 렌더·최종 확인 완료와 다르다.

각 작성자는 다른 두 작성자의 같은 라운드 원고가 생기면 교차 비평을 남긴다. 상대 파일 수정 금지. 요청·완료는 자기 기계 HANDOFF에 append하고 상태는 자기 NOTES.md에 쓴다. 기존 tmux 작성자를 중복 실행하지 않는다. Air는 자기 우선 업무와 자원 규칙을 지킨다.
