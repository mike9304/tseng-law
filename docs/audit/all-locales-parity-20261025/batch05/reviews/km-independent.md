## 필수 M01 — 통합증명 예외의 유효성 조건

704 본문 실제 문장:

> អ្នកកាន់ឯកសាររួមដែលមានមុខងារ ARC រួចហើយ ស្ថិតក្នុងករណីលើកលែង។

704 FAQ1 실제 문장:

> អ្នកដែលមានឯកសាររួមបញ្ចូលមុខងារ ARC មានករណីលើកលែង។

이유: ‘ARC 기능이 이미 들어 있다’ 또는 해당 문서를 ‘가지고 있다’는 표현은 문서가 현재 유효하다는 조건을 명시하지 않는다. EN704는 `valid combined document`를 전제로 별도 ARC 예외를 설명하고 F01도 유효한 통합증명이라고 한정한다. [현행 중문 이민법 제22조 제2항](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=D0080132)의 해당 유효 증명 문구도 직접 재열람했다. 만료된 통합카드를 가지고 있다는 사정만으로 예외에 들어간다는 읽기를 막아야 한다. 이 조건은 법적 예외의 범위이며 단순 수식 개선으로 취급하지 않는다.

최소 수정안 — 본문:

> អ្នកកាន់ឯកសាររួមដែលមានសុពលភាព និងមានមុខងារ ARC រួចហើយ ស្ថិតក្នុងករណីលើកលែង។

최소 수정안 — FAQ1:

> អ្នកដែលមានឯកសាររួមដែលមានសុពលភាព និងបញ្ចូលមុខងារ ARC មានករណីលើកលែង។

의미 보존: `ដែលមានសុពលភាព`로 유효성을 붙이고 기존 통합 기능·별도 ARC 예외를 유지한다. 입국 다음 날부터 30일과 대만 내 비자 발급일부터 30일은 바꾸지 않는다. 작성자는 지적에 동의했고 R1 고정 뒤 본문·FAQ를 함께 수정하기로 했다. 이 보고서 작성 시 원고는 아직 위 R1 SHA다.

## 선택 제안

### S01 / 706 — 짧은 문장의 대상 명료화

실제 문장:

> កាលបរិច្ឆេទលើកាតនៅតែមួយ។ មូលហេតុដែលធ្លាប់គាំទ្រវាអាចបានបញ្ចប់ទៅហើយ។

이유: `នៅតែមួយ`는 이 문맥에서 날짜가 하나라는 뜻인지 날짜가 그대로라는 뜻인지 덜 명확하다. 카드에 인쇄된 날짜와 사유 소멸의 관계를 보여주려는 문장이므로 ‘만료일이 그대로’라는 대상을 직접 쓰면 읽기 쉽다. 앞뒤 문단이 사유 소멸·허가 폐지와 예외를 정확히 설명하고 있어 별도 필수 법률 오류로 올리지 않았다.

선택 수정안:

> ថ្ងៃផុតសុពលភាពលើកាតនៅដដែល ប៉ុន្តែមូលហេតុស្នាក់នៅអាចបានបញ្ចប់ទៅហើយ។

의미 보존: 인쇄된 만료일이 변하지 않았더라도 거류 근거는 끝났을 수 있다는 같은 관계를 한 문장으로 묶는다. 이 문장만으로 계속 체류권을 만들지 않으며 앞의 제23-1조 적격 확인, 뒤의 제31조 예외는 그대로 둔다.

MONOTONY: §5.3 문장 분절 — `កាលបរិច្ឆេទលើកាតនៅតែមួយ។` — 모호한 단문을 따로 두기보다 ‘만료일’과 ‘사유 소멸’의 실제 관계를 한 문장으로 잇는다. 단문 비율을 낮추거나 높이기 위한 지적이 아니며 국소 선택 개선이다.

### S02 / 706 — 노동쟁송 주체의 선택 정밀화

실제 문장:

> ចំពោះវិវាទការងារ នីតិវិធីបណ្តឹងត្រូវកំពុងដំណើរការ; ចំពោះគ្រោះថ្នាក់ការងារ ត្រូវកំពុងព្យាបាល។

이유: 진행 중 쟁송과 치료 중 산재라는 필수 상태는 유지된다. 현재 문장은 ‘진행 중이어야 한다’는 필요조건의 설명이며, 앞뒤에서 각 예외의 별도 조건·NIA 판단·자동 체류권 부재를 밝혀 모든 고용주와의 분쟁에 충분한 자격을 보장하지 않는다. 따라서 추가 세부가 없다는 이유로 필수 반려하지 않았다. 다만 같은 문장에서 [이민법 제31조 제4항 제5호](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=D0080132)의 대만 고용주를 적으면 독립 독해가 더 정확해진다.

선택 수정안:

> ចំពោះវិវាទការងារជាមួយនិយោជកតៃវ៉ាន់ នីតិវិធីបណ្តឹងត្រូវកំពុងដំណើរការ; ចំពោះគ្រោះថ្នាក់ការងារ ត្រូវកំពុងព្យាបាល។

의미 보존: 노동쟁송의 상대방을 한정하고 현재 진행 중이어야 한다는 조건, 산재 치료 중 조건을 그대로 보존한다. 새로운 자동 체류권이나 기관 승인 보장은 추가하지 않는다.

### 직접 실행, 추출 경계와 §5

[독립 R2 실행·전체 diff·역복원·추출·구조 기록](../checks/km-independent-r2.json)에 실행 명령, 실제 exit/stdout/stderr, 현재 checker/profile SHA를 남겼다. Node24 환경의 정확한 공유 `--lang km` 결과다.

새 전체 배열은210구간이다. R1에서 직접 읽은207구간은 정확히 같고, 새3구간(704 유효성,706 만료일 연결,706 고용주 범위)은 실제 추출과 문단 문맥을 다시 읽었다. 706의 두 짧은 문장이 한 문장으로 연결돼 총계가211→210으로 변한 것이며 다른 종결 경계의 이동은 없다. 수정 FAQ는 리듬 분모에 포함시키지 않고 따로 읽었다. 704 목록 앞 콜론 도입 구간은 여전히 문법적 완문으로 주장하지 않는다.

§5 재점검: 현재 실측을 갱신했고, S01은 문장 관계를 구체화해 반영됐다. 새로운 짧은 구호나 기계적인 단문을 덧붙이지 않았다. 도입·문단 시작·인용 위치·주요 대비 설명·고지 직전 실질 결말은 네 치환 범위 밖이어서 그대로다. S01의 만료일/사유 관계와 S02의 두 조건을 실제 문맥에서 읽었으며 새 단조로움 반려 사유는 발견하지 못했다. 706 CV는 .478→.466으로 내려갔으나 여전히 기준 내이며 의미 개선을 점수 상승으로 오인하지 않는다.

길이 단위 `icu_dictionary_wordlike_units`와 원어 단어수 인증이 아니라는 한계, 중립 약어 `។ល។` 사례의 미지원 한계, 인간 원어민/법률 검수 부재는 R1과 동일하게 유지한다. 공유 도구나 profile을 수정하지 않았다.

### 구조·출처·입력 상태

gray-matter로 다시 파싱한 구조 오류0. 704 FAQ1의 M01 문장 외 모든 메타데이터가 R1과 같고, 모든 Markdown URL 값·순서 및 원본 이미지 SHA는 불변이다. 따라서 R1의 공식 URL13/15/14개·EN 누락0·마지막 출처 목록 누락0 판정도 유지된다. 발행일26일, 출처 확인일24–25일, audience km, author legal-ai-assistant, 세 FAQ, 가상 장면 캡션과 표기 제한을 재확인했다. 출처 URL을 새로 전수 접속했거나 운영 화면을 본 것으로 표현하지 않는다.

R2 종료 시 저자 기록·저자 final-manifest의 합의된 갱신 외 검수 입력의 추가 SHA 변화는0이다. R1 고정 전 LESSONS 자동 갱신 발견과 전문 재독 이력은 원문 그대로 남았다. 원고·저자 기록·R·공유도구는 검수자가 수정하지 않았다. 이 결과는 지정 원고의 독립 의미·문체 검수 종료이며, 브라우저 렌더링·공개 배포 또는 인간 전문가 승인을 뜻하지 않는다.
