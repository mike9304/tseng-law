# Japanese archive and search streamed hydration

The October4 Japanese/Vietnamese publication at `4f4329815944af765aa092cc013bd7d0bc36d136` recorded an actual React418 pageerror during the Japanese mobile journey. Its exact production URL/time was not captured. Two clean retries did not establish a fix; the batch was corrected to `PUBLISHED_WITH_OPEN_QA_ISSUE`, preserving its original reports.

An identical local production build reproduced React418 while delivering unchanged HTML in small chunks. Firefox1024B/16ms failed on `/ja/columns`; Chromium512B/12ms also failed on its labor-filter route. Completing the full journey exposed the same failure on `/ja/search`, including on the unchanged baseline. Local-only observation immediately before React's original throw recorded the archive expecting `div#ja-columns` while its hydration cursor was already on the existing BreadcrumbList child; search expected `div.search-tabs` while the cursor was on its first link. The document was still loading. These observations identify streamed hydration resumption inside an already-claimed wrapper; they do not retroactively identify which route produced the original production event or establish a complete React-internals root-cause proof.

Only these two Japanese routes now render their complete view through synchronous client boundaries with SSR enabled. The server still resolves publication eligibility, filtering, search, visibility and metadata. The archive transfers card fields only, sends no hidden repeater rows, and preserves independent schema visibility. Search transfers displayed hit fields only, never full documents/bodies/scores. Other search locales retain the same server view. Article content, media, canonical URLs, classification and privacy/byline policy are unchanged.

A smaller Suspense-only experiment was rejected: it hid the archive without JavaScript. Its failed evidence remains. The adopted view preserves the existing issue-board tabs, curated order and consultation links.
