# tseng-law.com — 3 AI 진단·토론 결과

2026-09-05 KST. 사용자 요청: 사이트의 부족한 점을 먼저 세 AI가 토론한 뒤 계획 작성. **이 문서는 최초 토론·계획 시점의 기록이다.** 이후 Grok 구현과 Codex 검수를 진행했으며, 현재 상태는 [최종 검수](FINAL-REVIEW.md)에 기록했다. 공개 반영은 아직 하지 않았다.

## 참여와 방법

- Grok 4.6: 사용자 경험·문의 동선의 독립 진단 → Fable/Codex 의견에 대한 2차 반박·정정.
- Fable 5.1: 상담 안내의 일관성·신뢰·운영 사실의 독립 진단 → Grok/Codex 의견에 대한 2차 반박·정정.
- Codex(현재 주 에이전트): 직접 공개 사이트 HTTP·실브라우저·키보드·접근성을 검증하고 두 보고를 반박·보강, 최종 우선순위 결정.

각 모델을 실제 CLI로 호출했다. Grok 응답 modelUsage는 `grok-4.6-build`, Fable 본문 응답은 `claude-fable-5-1`로 기록되어 있다. 공개 자료 기반 독립 보고 2개와 교차 토론 2개를 원문 보존했다. Fable 실행의 소량 Haiku 보조 메타데이터는 토론 참가자로 세지 않는다.

비공개 저장소 읽기를 포함한 Grok 실행은 자동 승인 검토가 외부 소스 전송 우려로 거절했다. 해당 실행을 진행하지 않고, 저장소 밖 임시 폴더에서 **공개 화면 관찰만 제공하고 도구·파일 읽기·MCP·메모리를 차단한 실행**으로 대체해 승인받았다. 최초 Fable 소스 읽기 실행은 API 연결 오류로 본문 토큰 0, 종료했다. Fable도 이후 공개자료만으로 토론했다. Codex의 로컬 소스 확인 결과는 외부 모델에 전달하지 않았다.

## 실측 범위와 한계

- 2026-09-05, 일회용 Chromium. PC 1440×900, 모바일 390×900/844. 기본 점검은 reduced-motion.
- KO 홈·연락처·비용·변호사, EN/JA 홈·연락처, ZH-HANT 홈. KO 검색 결과. 화면 및 href를 읽었으며 실제 문의 이메일을 보내거나 예약·AI 제공자를 호출하지 않았다.
- 연결된 앱 브라우저가 없어 별도 일회용 Chromium을 사용했다. 사용자 브라우저 프로필·로그인 세션에 접근하지 않았다.
- 검색엔진이 반환한 예전 연락처의 LINE/Kakao 안내는 직접 읽은 현재 페이지와 달라 근거에서 제외했다.
- `/zh`의 404는 검사자가 잘못 추정한 경로다. 실제 중국어 전환 경로 `/zh-hant`는 정상이다.
- 자동 접근성 검사는 제한된 페이지/상태만 다룬다. 위반 0은 전체 접근성 보증이 아니다. 실제 전환율·메일 수신·응답시간·검색엔진 색인·전체 성능·모든 빌더 기능은 이번 조사로 입증하지 않았다.

## 최종 발견 사항

| 우선순위 | 발견 | 근거 | 판정과 개선 방향 |
|---|---|---|---|
| 1 | 검색 결과 작은 글자 대비 부족 | `/ko/search?q=법인`: 13.12px 보통 굵기 `#86968b` / `#fff`, **3.11:1**, PC·모바일 각각 13개 요소 | 재현된 접근성 문제. 검색 보조글자 색을 4.5:1 이상으로 변경하고 다른 배경도 확인 |
| 2 | 상담 언어·이메일 양식 불일치 | 홈·프로필은 일본어 상담 안내. KO/EN/ZH-HANT 메일 희망언어에는 일본어 없음. JA에는 4개 모두 존재 | 확인된 표기 불일치. 접수·직접상담 역할을 구분하고 이미 확인된 일본어 안내 누락부터 정정 |
| 3 | 예약 버튼 표현과 실제 경로의 차이 | `/ko/pricing` ‘상담 예약하기’ href가 `mailto:` | 예약 불능이라고 단정하지 않음. ‘이메일로 상담 일정 문의’로 실제 행동 명시 |
| 4 | 연락처 페이지에서 접수 수단이 너무 뒤에 있음 | 390×844 첫 이메일 링크 문서 y: KO 약1780px, EN 약1969px, JA 약1834px | 정보 우선순위 개선. 첫 화면에 이메일·작성·복사·최소자료 안내, 준비 안내는 뒤로 유지 |
| 5 | 제작 과정 문구가 고객 페이지에 노출 | 홈 칼럼 소개 ‘실제 수집된 칼럼 본문과 이미지를 기반으로…’ | 독자가 얻는 법률정보·주제 안내로 교체 |
| 6 | 홈 첫 화면에서 업무 설명·문의 경로가 늦게 나옴 | 첫 화면은 브랜드+본문 진입 버튼. 클릭 후 H1·상담 CTA 정상 | 기능 고장이 아닌 설계 선택. 인트로 유지, 대만 법률 업무 설명과 연락처 링크 보강안 |

검색 대비 기준: [W3C WCAG 1.4.3 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). 일반 크기 글자의 최소 대비는 4.5:1이다.

연락처 위치의 y는 문서 기준으로 측정했다. ‘1780px’가 이메일 접근 불능을 뜻하지 않는다. 메뉴에는 이미 이메일 CTA가 있고 홈 진입 후 주 CTA는 y≈345px이다.

## 실제 토론에서 달라진 판단

| 쟁점 | 첫 의견 | 반박·추가 검증 | 최종 판정 |
|---|---|---|---|
| 홈 인트로 | Grok이 첫 화면 문제를 1순위로 제안 | Codex가 클릭·Tab→Enter·H1 노출 확인. Fable도 삭제 반대 | Grok이 1순위 철회. 브랜드 연출 유지, 보강은 후순위 |
| reduced-motion | 즉시 본문 노출을 필수 수락 기준으로 제안 | Codex가 정적 인트로 우회 의무의 근거 부재 지적 | 두 모델 모두 접근성 위반 주장 철회 |
| 언어 불일치 | Fable 1순위, Grok 5순위 | Codex가 실제 mailto 디코딩에서 일본어 누락 확인 | 세 AI 모두 우선 수정 동의. 영어 불가라고 단정하지 않음 |
| 연락 채널 추가 | 전화·메신저·새 폼·회신시간 제안 후보 | 현재는 공식 메일+복사+프리필이 이미 존재. 운영 사실 불명 | 기존 이메일 접수 개선. 새 번호·채널·SLA를 만들지 않음 |
| 개인정보 안내 | Fable이 연락처 폼 부재를 근거로 문구 삭제 제안 | Codex가 한 페이지의 폼 부재는 전역 부재 증거가 아니라고 반박 | 삭제 권고 철회, 최소정보·민감정보 안내 보존 |
| 검색 대비 | 1차 보고에는 없었음 | Codex 자동 검사 및 PC·모바일 반복 재현 | 두 모델이 수정에 동의. 최종 실행 순서는 Codex가 1순위 배정 |

Fable은 언어 정합을, Grok은 언어→CTA→연락처를 앞세웠다. **최종 계획은 독립적으로 바로 고칠 수 있는 검색 대비를 먼저 처리하고 언어·CTA·연락처를 이어서 처리한다.** 우선순위가 전원 동일했다고 주장하지 않는다.

## 유지할 강점 / 이번에 결함으로 확정하지 않은 것

- 홈 진입 버튼과 키보드 Tab→Enter 정상(390/1440), 모바일 메뉴 열기·Escape 닫기 정상.
- 검사 페이지에서 가로 넘침·pageerror 없음. KO 홈 진입 후/연락처/가격의 이번 axe 자동 검사에서는 위반 없음.
- KO 홈 canonical, KO/JA/EN/ZH-HANT+x-default alternate, JSON-LD 4개가 존재한다. 이는 SEO 전체 검증이나 색인 증명이 아니다.
- 명시된 비용, 담당자 소개, 지도, 이메일 주소 복사, 프리필 메일, 민감정보 안내가 이미 있다.
- 타이베이 전화, 직접 영어 상담 범위, 회신 소요시간, 리뷰 수치 기준일, 리뷰 이벤트 조건은 운영 사실 확인 대상. 없는 사실을 채워 넣지 않는다.
- 이벤트 문의 href가 일반 상담과 같은 제목을 쓰는 것은 확인했다. 실제 진행 중인 이벤트인지 확인한 뒤 목적 분리 여부를 결정한다. 위법·리뷰 조작이라는 주장은 하지 않는다.
