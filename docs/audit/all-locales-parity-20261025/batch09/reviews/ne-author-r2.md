# NE6 — 독립 R1의 필수3·선택5 반영

Root가 직접 수정했다. 원 저자 보고서와 독립 R1을 그대로 보존했고, 직전 원고6편은 `checks/ne-independent-r1-source-snapshot/`에 고정했다. 독립 보고서·필수/선택 문장안을 읽고, 중간 출력 누락은 나누어 보충했다. ZH918/919/920 정본 전문을 다시 읽었다. 17:05 LESSONS SHA도 변하지 않았음을 확인했다.

필수 지적은 모두 수용했다.918에 건설사의 지연이자 지급 판단이 유지됐다는 문장을 복원했다.919FAQ2는 조사 완료를 기다리지 않는 보호와 공정 조사 병행,FAQ3은 민간 회사에 공무원 절차를 그대로 적용할 수 없다는 원래 질문 범위로 되돌렸다.920의 열쇠는 본인이 보관했다는 설명을 위원회에 넘길 의향으로 본문과FAQ 두 곳 모두 고쳤다. ‘주장이 사실이라고 가정해도’라는 법원의 조건부 판단은 그대로다.

R1 저자 기록의 FAQ 의미 보존 주장은919FAQ2/3에 관해 불충분했고,920의 초기 열쇠 설명은 잘못됐다. 이는 이번R2에서 수정한 의미 오류다. 초기 숫자·URL 일치와 편집 역복원은 그 오류를 찾아내는 의미 검수를 대신하지 않았다. 원 기록을 고쳐 처음부터 맞았던 것으로 만들지 않는다.

선택 S01–S05도 채택했다.915의 금액을 실제 수령액이 아니라 중재판정에서 정한 금액으로 명료화했다.916의 ‘접촉/청소’를 화학물질 노출과 오염 제거로 풀고,918의 축약 `ऋणपत्र`를 대출 관련 서신으로 두 곳에서 명확히 했다.915/916/921의 연락 경로 문장은 같은 문단 앞쪽으로 옮겨, 실제 계약 유형·거래 날짜·지급/잔액 대조 내용이 실질 결말을 맡게 했다.921FAQ2에 언제든 계약 종료가 가능하다는 기존 본문의 내용을 추가했다. 이 선택 사항을 필수 법률 오류로 재분류하지 않았다.

`checks/ne-author-review-r2-edits.json`은 정확한 문맥을 포함한16치환을 담는다. 첫 역복원 시도는 두 열쇠 표현의 수정 결과가 같고 ‘대출 관련 서신’도 원래 다른 곳에 있던 표현이어서, 짧은 조각의 전역 역치환 검증이 AssertionError로 실패했다. 모든 의도한 원고 수정은 이미 적용된 상태였다. 그 실패는 `ne-author-review-r2-first-proof-error.json`에 남겼다. 보존 R1에서 전체 문맥 행으로 치환을 다시 구성해 현재 원고6과 일치하는지 먼저 확인한 뒤, 같은16기록의 순방향·역방향6/6 일치를 확인했다. 이 증명 재실행은 원고를 추가로 바꾸지 않았다.

공식URL 순서·숫자 순서·이미지·가상표시·날짜·작성자 메타는 보존했다. FM은916FAQ,918SEO,919FAQ2/3,920FAQ,921FAQ가 바뀌었으므로 불변이라고 쓰지 않는다. 입력17개의SHA는 종료 때도 일치한다. 규칙5절에서 같은 도입 분포와 문단 시작 한도를 유지했고, S04의 연락처 반복 결말은 실제 사례 내용이 끝나도록 정리했다.
