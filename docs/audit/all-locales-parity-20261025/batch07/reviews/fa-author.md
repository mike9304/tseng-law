# B7 FA 여섯 편 — root 직접 집필·자가검수

현재 판정은 저자 단계 완료, 독립 의미 검수 대기다. 여섯 편을 root가 직접 페르시아어로 작성했다. Kimi나 다른 언어 초안을 작성자로 대신 표시하지 않는다. 원어민·변호사 승인, 실제 RTL 렌더링 또는 공개 배포를 뜻하지 않는다. 최종 파일과 검사 연결은 [manifest](../checks/fa-author-manifest.json), 입력과 실제 도구 SHA는 [입력 기록](../checks/fa-author-inputs.json)에 있다.

## 실제 검사와 경계 독해

초기 공유 실행에서919/921의 길이 CV가 실패했고 전체 명령 exit1이었다. 이 자료는 `fa-variety-initial.json`에 남아 있다. 수정4편 실행에서도919만 .448로 남아 exit1이었으며 `fa-variety-author-r1.json`을 보존했다. 이후919의 일반명제를 구체 질문으로 바꾼 선택 실행은 exit0/FAIL0이다. 이미 통과한 동일 SHA의 다른 파일은 다시 전수 실행하지 않았다. 따라서 이전 배치 명령 자체를 exit0으로 다시 표시하지 않으며, 현재 원고별 증거 행이 모두 OK임을 manifest에 연결한다.

초기249개 추출문장을 모두 실제로 읽었고, 최종 변경9문단의 추출문장을 별도로 다시 읽었다. [최종247분절](../checks/fa-final-boundaries.json)은 같은 SHA의 불변 결과와 실제 변경 결과를 합친 자료다. 날짜, 페르시아 숫자, 조문 하이픈, 중국어 사건번호가 문장 중간에서 잘린 것은 발견하지 못했다. 이것은 논리 텍스트의 경계 확인으로, 브라우저 RTL 표시 확인이 아니다. 단위는 해당 공유 FA 프로필의 단어 단위이며 다른 언어의 숫자와 직접 비교하지 않는다.

구조 검사도 초기6개, 변경4개, 마지막919 한 개를 현재 SHA로 연결해 errors0이다. 처음 wrapper가 B7에 없는 research 경로를 찾은 ENOENT와, 단일 ZH 선택 후 빈 EN 그룹을 검사기에 보낸 오류도 별도 기록했다. B6 입력 경로 명시·빈 그룹 건너뛰기로 wrapper만 고쳤다. 공용 검사기의 검수 항목은 지우지 않았고 현재 상태는 계속 REVIEW_REQUIRED다.

§5 확인: 여섯 도입은 금액이 걸린 중재 결과, 거래 전 보고서, 대출편지 당시 집 상태, 심의 전 발표, 충전선 경로, 게임 잔액 청구에서 각각 시작한다. 아주 짧은 완결문이 각 글에 둘 이상 있고 법적 조건이 긴 문장 사이에 설명·장면·질문이 들어간다. 문단 첫 단어를 읽어 반복3회를 피했고 인용 없는 실질 문단도 있다. 모든 문단을 조문과 예외의 틀로 만들지 않았다. 말미의 출처 확인·범위 고지 앞 실질 결말은 각각 청구 변경 기록, 보고서에서 자산 이동까지의 경로, 통지 종류, 조사 응답 기록, 허가와 실제 시공, 돈의 충전·변환·사용에 연결된다. 굵은 강조·공개 작성자 이름·허구의1인칭·훈계형 체크리스트 제목은 없다. 규칙보다 법적 의미·숫자·공식 출처를 우선했다.

다음 단계는 독립 의미 검수와 실제 RTL 화면 확인이다. 여섯 파일은 원고별 SHA로 동결했고 이 저자 기록은 그 두 단계를 대신하지 않는다.
