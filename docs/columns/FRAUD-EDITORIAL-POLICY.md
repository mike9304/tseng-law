## 사실과 출처

자료를 직접 열어 본 뒤 작성한다. 법령·공식 기관·판결 원문 등 1차 자료를 우선하고 검색 결과 요약이나 다른 칼럼만으로 법률 결론을 확정하지 않는다. 참고한 예전 글도 최신 사실의 증거로 대신 쓰지 않는다.

내부 claim ledger에는 각 중요한 주장, 본문 위치, 출처 URL·발행 기관·관할, 근거 조문 또는 문단, 발행·개정·시행일, 실제 확인일, 적용 조건과 한계를 남긴다. 자료에 날짜가 없으면 없다고 적는다. 실무상 제안이나 자료에서 도출한 해석은 법정 의무와 구별한다. 시행 전 조문, 과거 사건의 법령, 현재 절차를 섞지 않는다.

독자가 검증할 수 있도록 본문의 관련 주장 가까이에 직접 출처 링크를 붙이고 참고 출처도 정리한다. 판결은 법원·사건번호·선고일·심급과 확인한 범위를 명시하며 한 사건의 판단을 일반 규칙으로 확대하지 않는다. 확인할 수 없는 수치·통계·사실은 삭제하거나 확인 범위를 좁혀 다시 쓴다. 돈을 되찾거나 사건에서 이긴다는 보장은 하지 않는다.

## 반복 검수와 발행 증거

1. 작성자는 독자 기획서, 초안과 출처별 claim ledger를 함께 낸다.
2. 작성자와 분리된 검수자가 법률·출처 정확성과 문체를 각각 검수한다. 법률 검수는 주장과 원문·시행 여부·조건을 대조하고, 문체 검수는 실제 문장을 읽는다. 모델 검수를 변호사 또는 원어민 검수로 표시하지 않는다.
3. 첫 두 문단은 문장별 삭제 검사를 하고 직전 같은 언어 글 3편의 도입·소제목·끝맺음과 비교한다. 수정 기록은 `원문 → 문제와 이유 → 수정안 → 보존한 사실·조건`으로 남긴다. AI 탐지기나 금칙어 검색만으로 통과시키지 않는다.
4. 작성자가 지적을 수정한 뒤 검수자가 해당 문장·근거를 다시 대조한다. 검수 범위와 남은 지적을 기록하고 중대한 사실·법률·의미 문제가 하나라도 남으면 발행하지 않는다.
5. 격리된 배포 체크아웃에서 변경 범위, frontmatter·내부 링크·출처·이미지 경로, 필요한 테스트, typecheck·lint 및 클린 빌드를 확인한다. PC와 모바일에서 글·출처·이미지·언어별 탐색을 실제로 확인한다. 관계없는 작업을 함께 배포하지 않는다.
6. 발행 후 배포 상태와 커밋을 확인하고 운영 URL을 다시 읽어 본문·출처·이미지가 검수본과 일치하는지 검증한다. 파일 해시, 실제 URL, 확인일과 화면 근거를 `docs/audit/`에 남긴다. 로컬 빌드 통과를 운영 반영 완료로 기록하지 않는다.

사용자는 이번 요청 범위의 검수·수정·사이트 배포를 이미 승인했다. 위 검수·기술 게이트를 통과한 요청 범위는 같은 허가를 다시 묻지 않고 진행한다. 이 승인으로 이메일·DM·소셜 발송, 새 자동 게시 일정 또는 범위 밖 변경까지 확대하지 않는다.
