# 형사소송 칼럼 401–404 발행 검수

2026-10-07. 범위: 한국·대만·미국·일본·베트남 독자를 위한 4개 주제, 5개 언어, 20편 및 `/[locale]/criminal-litigation` 게시판. 검색량·예상 유입 수치는 측정하거나 주장하지 않았다. 기존 체포·피의자 조사 안내와 겹치지 않는 증인, 합의, 불기소 불복, 압수물 반환의 절차적 질문을 선택했다.

원고 식별은 `FINAL-CONTENT-SHA.json`을 사용한다. 사용자 요청에 따라 GPT-6 Astra max 검수자 A·B·C가 서로의 보고서를 읽지 않고 20편 전체와 공식 자료를 각각 대조했다. 세 사람의 최종 원고 판정은 모두 APPROVE다. 독립 AI 검수이며 변호사 또는 인간 원어민의 검수를 뜻하지 않는다. 초기 지적과 수정 후 재검수는 `reviews/`에 보존한다.

## 문장 다양성 규칙 5절 자기 점검

1. 최종 SHA 기준 KO·EN·JA·ZH 16편을 실제 지원 언어로 검사했다. 모두 FAIL 0. 로그는 `variety-final.log`. VI는 도구 미지원이므로 다른 언어 옵션으로 통과시켰다고 주장하지 않는다. 세 독립 검수자와 작성자가 수동으로 읽었다.
2. 실제 첫 두 문단과 같은 언어의 직전 글 3편을 비교했다(`opening-comparison.json`). KO·EN·JA·ZH는 최신 main의 375·374·373, VI는 203·070·040과 비교했다. 401은 문서상 지위, 402는 미지급 상태의 취소 효과, 403은 송달 기한, 404는 유치 필요성으로 시작한다. KO·JA의 402·404는 모두 질문형이지만 같은 가상 장면을 복제하지 않으며 질문이 곧바로 해당 사실의 답으로 연결된다.
3. 짧은 문장이 법적 구별을 맡도록 고쳤다. 길이 수치만 맞추는 403 JA 질문과 404 EN 추상 단문은 제거했다. 조건·예외를 잘라 법적 의미를 바꾸지 않았다.
4. 문단 시작의 연속 반복과 시작어 분포를 검사하고 수동 확인했다. 같은 시작어의 기계적 나열을 남기지 않았다.
5. 문서 확인·증거 보관·실제 질문 문단을 두어 조문 뒤 단서를 붙이는 구조만 연속되지 않게 했다. 인용 없는 문단도 독자에게 필요한 내용을 담는다.
6. 대비 표현을 검사했다. 합의와 취소, 반환과 임시 반환, 재의와 자소 허가 등 실제 혼동 가능성이 있는 구별을 보존했다.
7. 마지막 실질 문단은 해당 글의 문서·송달 기록·압수 영수증 등으로 마친다. 복제된 판촉 문구나 상담 경험담은 없다.
8. KO 합니다체·JA ですます체를 유지했다. 해당 종결어미 WARN 8건은 형식체 일관성 안에서 수동 검토했고, 경고를 없애려고 말투를 섞지 않았다. 굵은 강조·우회 태그·가공 1인칭 경험은 없다.
9. 조문·숫자·기한·예외·출처·내부 AI author·AI 이미지 표시를 최종 원고 SHA와 함께 다시 확인했다. 문체보다 정확성을 우선했다.

## 게시판 및 발행 확인

5개 언어 게시판은 같은 언어의 `criminal-litigation` 태그 글만 싣는다. 각 4편이며 언어 버튼, 일반 칼럼, 형사 서비스 안내와 연결한다. VI는 실제 작성한 게시판만 허용하고 지원하지 않는 언어의 형사 게시판을 만들지 않는다. canonical·언어 대체 링크·sitemap을 추가했다.

서비스 안내의 모든 형사사건에 6개월이 적용된다는 기존 문구를 정확한 범위로 수정했다. CMS가 서비스 slug를 변경해도 `sourceSlug`로 형사 서비스를 인식한다. 이미 저장된 과거 기본 문구만 바꾸고 사용자가 직접 작성한 문구를 보존한다. 실제 검수 근거 없이 표시되던 형사 페이지의 변호사 검수 문구는 제거했다.

배포 전 검증 결과는 `preflight.md`에 기록한다. 새 칼럼은 승인된 원고 SHA와 동일한 파일만 발행하며, 발행 뒤 운영 사이트 검증은 별도의 완료 증거로 남긴다.
