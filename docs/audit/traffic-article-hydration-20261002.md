# 교통 칼럼 초기 hydration 수정

게시판 수정 `e6da941` 후 운영 게시판은15/15 통과했지만077·078 글의 Firefox 초기 로드에서 React418이 각각 관찰됐다. 사진·메타·접근성·재생은 작동했으나 오류 게이트 실패를 보존하고 글 페이지의 공통 경로를 조사했다.

## 재현과 변경

로컬 프로덕션의 원본 HTML을2,048바이트씩12ms간격으로 전달하면077/078 각3회 중1회 오류가 재현됐다. 공개 번들 계측·403우회·오류 무시는 사용하지 않았다. 교통 게시판과 마찬가지로 점진적으로 전달되는 서버 요소 트리와 초기 hydration의 경합 범위를 좁혔으며, React 전반의 결함으로 단정하지 않는다.

기존 JSX를 `ColumnDetailView`로 옮겨 한 구현을 공유한다. 교통 분류 글은 서버가 완성한 공개 데이터로 `TrafficColumnView`를 렌더링한다. 이 일반 클라이언트 경계도 서버 HTML을 생성하므로 본문·사진·단계 이미지·구조화 데이터·JavaScript 없는 접근을 유지한다. 마운트 후에만 출력하거나 SSR을 끄지 않는다. 비교통 글은 같은 뷰의 서버 경로를 사용한다. 파일/CMS 게시본 조회, 분류, 공개 템플릿 결정, 메타/JSON-LD 계산은 서버에 남는다. 이전/다음 글은 제목과 slug만 전달하며 다른 글 본문을 넘기지 않는다.

원래 콘텐츠·이미지·영상 파일과 URL/canonical은 변경하지 않는다. 빌드 표시상 칼럼 라우트 최초 JS가197kB에서255kB로약58kB 증가한다. 이 비용을 숨기거나 런타임 성능 개선으로 표현하지 않는다.

## 독립 검수 및 숨김 조건

사용자가 연결한 Studio 기존 ChatGPT 로그인 Codex CLI의 실제 런타임 모델 `gpt-6-astra`로 통합 코드만 정적 검수했다. 첫 결과는 BLOCK: 본문/SEO 블록이 숨김일 때 목차 제목·FAQ가 데이터 props로 남을 수 있다는 유효한 지적이다. 해당 후보는 공개하지 않았다.

본문이 숨겨지면 본문·목차·도해·FAQ 목록·추천·이전/다음 본문용 데이터를 비우고, SEO가 숨겨지면 구조화 데이터도 보내지 않는다. 본문 숨김/SEO 공개일 때 FAQ JSON-LD가 공개되는 기존 동작은 유지한다. 실제 서버 페이지를 호출하는3개 테스트로 각 조합의 직렬화 데이터까지 확인했다. 실제 gpt-6-astra 재검수에서 이전 차단 해소 PASS를 받았다. 두 호출 모두 도구0, 정적 검수에 한정하며 실제 테스트를 실행했다고 주장하지 않았다. 원문과 실행 모델/사용량은 작업 폴더 인계에 보존한다.
